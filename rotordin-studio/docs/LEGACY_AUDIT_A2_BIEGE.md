# A2 — BIEGE14 adapter audit

Baseline: `main@40babc4d63bebfbd876bae744e44541188ca4a7f`.

## Source functions audited

- `frmMain.efetua_calculo`
- `frmMain.ha_cargas_com_empuxo_magnetico`

## Execution order in VB6

```text
sort grdCargas by Xi
→ exporta_biege
→ ExecCmd biege input output (60 s wait)
→ check output file exists
→ le_NKRIT(first)
→ le_NKRIT(second)
```

The React adapter currently implements **serialization and parsing only**. It deliberately does not spawn the executable yet.

## Header

Current source writes:

```text
BIEGE14
''
''
'MM'  2 2.06E+011 7850 'JA'|'NEIN'
```

The plot flag comes from `Check2`.

## Geometry

For each grid row:
- accumulated end position is written with six decimals;
- D is written with six decimals;
- D_F is written when positive, otherwise 0.0.

This confirms that D_F is a taper modifier, not a mutually exclusive shaft section type.

## Ribbed / hollow block

Global model selection:
- ribbed present → `'ST'`
- else hollow present → `'HL'`
- otherwise → `'KEIN'`

For ribbed rows the current source derives:

```text
ribHeight = (DPCT - D) / 2 - B
```

and writes rib height, A, B, C, NR_COST plus trailing zeros.

## Loads

Before serialization, `efetua_calculo` sorts the load grid by Xi.

`exporta_biege` writes:
- concentrated: LC = 0 and Xi > 0;
- distributed: LC > 0, writing Xi, Xi+LC, KG, 0.0 and Empuxo flag.

The Xi > 0 condition means a point load at the origin is silently omitted by VB6. A2 preserves this behavior for compatibility but emits `BIEGE-POINT-ORIGIN-001`.

## Magnetic thrust

If any Empuxo flag is 1, VB6 refuses to run unless the configured `EINBIEGE.DAT` exists.

The target runner must strengthen this: existence alone is not sufficient. The file will be copied into the per-run workspace and tied to the run manifest/hash before solver execution.

## Bearings

The current BIEGE writer supports a single scalar stiffness per bearing:
- scalar zero / "Infinito" → support type 1 and 0.0;
- finite scalar → support type 2 and scalar stiffness.

The React domain keeps this scalar exactly.

### Legacy ordering defect

VB6 reorders bearing **positions** if bearing 1 lies to the right of bearing 2, but still reads `cmbEntrada(0)` for the first output and `cmbEntrada(1)` for the second. Therefore reversed bearings can be serialized with mismatched stiffness.

The TypeScript adapter intentionally sorts whole bearing entities by position, keeping coefficient ownership correct.

## NKRIT

Legacy behavior:
- first call with `emp_magn=True` returns first NKRIT;
- second call with `emp_magn=False` returns the second NKRIT if present, otherwise zero.

A2 separates this into:
- `parseNkrit`: return all NKRIT values in source order;
- `interpretNkrit`: attach ordinary/magnetic meaning using project context.

This avoids embedding the legacy UI calling convention in the parser.

## Why ibiege/temp.txt is not yet a byte Golden Master

The checked-in `ibiege/temp.txt` uses formatting/layout that does not match the currently audited `exporta_biege` implementation in several sections. It is useful historical evidence, but it is **not promoted as the byte-level oracle** for A2.

Before solver execution is enabled we still need a current production case generated by the authoritative VB6 executable.
